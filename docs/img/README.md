# Screenshots for Phase 7

These are the manual captures referenced by `docs/phase-notes/phase-7.md`.
They are **not** generated by tests; take them from a running console so the
review shows real data. Use a ~1440 px window, the default light theme, and the
sidebar visible. Do not include `.env`, tokens, or a live GitHub URL.

Prerequisites:

```powershell
docker compose up -d --wait postgres
.venv\Scripts\dqs demo --yes --reset          # populated dqs_demo (resolved incidents)
.venv\Scripts\python -m streamlit run ui/app.py
```

For `03-incident-approval.png` the incident must be paused at
`awaiting_approval`: either run `.venv\Scripts\dqs demo` interactively and leave
the terminal at the approval prompt while you capture the UI, or run
`.venv\Scripts\dqs incident run <uuid>` on a faulted incident (it stops at the
gate). Do not click Approve/Reject while capturing.

| File | Page | What must be visible |
|---|---|---|
| `01-incidents.png` | Incidents | Sidebar database = `dqs_demo`; filters; table with at least two statuses. |
| `02-incident-detail.png` | Incident detail (top) | Status metrics, violations, agent timeline, root-cause card with category/evidence/confidence (“model-reported, uncalibrated”), impact models and exposure owners. |
| `03-incident-approval.png` | Incident detail (bottom) | A fix attempt with PASS/FAIL checklist and observed values, the diff viewer, the publication row, the dry-run banner, and Approve/Reject. |
| `04-benchmark-pilot.png` | Benchmark | Select `20261023T135123Z_openai-gpt-oss-120b.json`; pilot/partial warnings, provenance (model, date, git SHA, fingerprint, harness/prompt hashes), infra-error metric, overall and per-kind tables. |
| `05-contracts.png` (optional) | Contracts | Status counts, contract table, and one YAML block. |

The pilot results file is a small operational run (`catalogue_size=4`) and is
supposed to show the orange “Pilot run” and “Stopped early” warnings. Do not
edit or rename it.
